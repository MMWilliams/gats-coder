Harnesses grow, then models absorb them

2:55–4:25 · 1 press · timeline plays itself
“Here's the full lineage.”
The harness finds what works, training absorbs it, scale makes it absorbable. The check can't be absorbed.
  • Five lanes: context, reasoning, tools, permission, check.
  • Chain of thought: PaLM 540B on GSM8K 18% → 57%, only at ~100B parameters. Not scale alone, not the prompt alone.
  • RL trained it into the weights against a checker: R1's rewards were rule-based (right answer, tests pass).
  • Frontier agents (Claude Code, Codex, Antigravity) run a simple loop: think, call a tool, read, repeat.
  • Can't absorb: what's true now, what it may touch, what happened.
  • → “Models absorb procedures. They can't absorb the check.” Bottom lane is the thinnest.

Terms

Harness
Everything around the model: context, tools, permissions, loop, checks.
RL
Reinforcement learning: training on rewards for outcomes.
GSM8K
A benchmark of grade-school math word problems.

Today's harness is tomorrow's model

4:25–6:05 · 3 presses
“Here's the mechanism behind that coupling…”
Models absorb procedures, never the check. Build sensors, gates and the record outside the model.
  • Traces become training data; checks become rewards. Wrappers become weights.
  • → Absorbed: step by step → reasoning models; voting → self-checking; ReAct text → native tool calls; tree search → backtracking.
  • R1-Zero learned to write “wait” and recheck from rewards alone.
  • → Next to go: compaction, subagents, skills and rules, plan search (GATS too).
  • → Never absorbed: the check. Stronger models game tests more (ImpossibleBench); METR caught o3 reward hacking in 30% of RE-Bench runs.

Terms

Goodhart's law
When a measure becomes a target, it stops being a good measure.
Reward hacking
Scoring well by exploiting the scorer instead of doing the task.

Seven gaps that limit long-horizon agents

8:05–10:05 · 8 presses, one per tile
“So what stops that line? I see seven gaps, and each one has a number.”
A better model shrinks these. It doesn't remove them.
  • → Reliability: at 80% success, Mythos 17 h → 3 h. 99%/step is 37% after 100 steps. tau-bench: 61% once, under 25% on 8 of 8.
  • → Trust: GPT-5 passed 76% of impossible tasks by gaming tests (one SWE-bench variant).
  • → Auditability: EU AI Act Art. 12: lifetime event logs, from Dec 2027.
  • → Reproducibility: 80 different answers in 1,000 at temperature 0. Batch size changes the order of float additions.
  • → Planning: o1-preview 98% on Blocksworld, ~24% at 20 to 40 steps.
  • → World models: an agent deleted a production database, then said rollback was impossible. It wasn't.
  • → Groundedness: AlphaGeometry 25 / 30 (previous best 10), a symbolic engine checking the model.
  • → Summary tile.

Terms

Neuro-symbolic

If the gaps closed

10:05–11:30 · 5 presses
“Suppose those gaps closed. Start with arithmetic.”
An independent check moves the 37% cliff from step 100 to step 1,000.

The LLM is the last resort (GATS)

11:30–13:25 · 5 presses
“GATS is the planner, from my paper with my co-author, Dymitr Nowicki.”
The LLM is the last resort, and plan quality doesn't depend on the model.
  • NYC taxi transformer (NeurIPS 2024): near-perfect directions, impossible map. Close 1% of streets: ~100% → 67%.
  • Today's agents: skilled sailors without a chart. GATS has a chart, checks it at every waypoint, fixes it.
  • UCB1 tree search over a persistent state graph picks every action.
  • → → → L1 symbolic contracts (exact, free) · L2 statistics from its own runs · L3 cached LLM, new transitions only.
  • → Stress test: GATS 100%, LATS 88.9%, ReAct 23.9%. 0 LLM calls during planning.
  • → Live Llama 3.2: LATS under 1%, GATS stays at 100%.

Terms

UCB1
Upper confidence bound: pick the option with the best average result plus a bonus for options tried less.
State-transition graph
A map of states and what each action did from each one, kept between runs.
LATS / ReAct
LATS: Monte Carlo tree search with the LLM as evaluator. ReAct: the reason, act, observe loop.

Keep the search space small

13:25–14:15 · 2 presses
“It has a hard limit, and it's in the paper.”
Search a few coarse actions. Put the open-ended work inside one checked step.
  • Breaks down past ~20 actions or depth 10: 20^10 ≈ 10 trillion sequences.
  • → Five plan actions: RunSuite, AuthorPatch, ApplyPatch, Commit, CreatePR. 5 actions, 4 deep: 625.
  • → The LLM writes the diff inside one step. The test suite decides.
11

Give the model zero trust (LEDGER)

14:15–16:10 · 8 presses
“LEDGER is the experiment: how reliable can a coding agent get if the model gets zero trust?”
To know what your agent did, ask the record, not the model.
  • → → → → GATS plans · the LLM writes a patch, nothing else · sensors decide what's true · the journal records everything.
  • → It can't set state: sensors say tests pass, repo clean, step recoverable.
  • → It can't claim success: a claim that doesn't match the sensors is an INCIDENT.
  • → It can't pick or run actions: GATS picks, gates hold risky ones, it escalates “infeasible”.
  • Cost: flexibility. It does far less than Claude Code.
  • → Terminal: ledger why (recorded search table) · replay (bit for bit) · verify-chain (one edited field caught).

Terms

Sensor
Code that measures state (run the tests, check git status). The model never sets it.
INCIDENT
A logged mismatch between what the model claimed and what the sensors saw.
Gate
A risk-class check before an action runs; irreversible actions need it.
Bit-exact replay
Rerunning the journal reproduces every decision exactly.

What zero trust bought

16:10–18:05 · 5 presses
“What did zero trust buy?”
The fix for a false success signal was a sensor, not a better model.
  • Say it: not a head-to-head on the same tasks.
  • → Impossible task: games tests (76%) vs says “infeasible”.
  • → Weak model: ReAct 36%, LATS under 1% vs 100%.
  • → Same run twice: 80 answers in 1,000 vs bit-exact replay.
  • → The record: a transcript vs a hash chain.
  • → crc: test claimed CRC-32 is linear over xor; all-ones start + final xor make it affine. Claude rewrote the test 4 of 4 times; my journal said success.
  • Fix: test edits refused + a sanctioned “infeasible”. Local 27B named the contradiction, 10/10.
  • “I'm a little embarrassed by that one, and I'm glad it happened.”

Terms

Affine vs linear
Linear: f(a xor b) = f(a) xor f(b). Affine adds a constant: f(a xor b) = f(a) xor f(b) xor c.

The model is a part you swap

“[Read the line. Pause.] Confidence is not evidence.”
“Tests pass” is a claim. The test output is evidence.

  • → The LLM moves down the stack; verification is where products differ.

15

We can only prompt what we can foresee

21:15–23:15 · 3 presses
“Last thought. We can only prompt what we can foresee.”
Prompts scale with our foresight. Plans scale with the agent's.
  • Thirty scenarios: you write the five you thought of; it guesses the rest and grades itself.
  • Responsibilities have no final outcome, only states to keep.
  • Ship's watch: standing orders, a “call me if” list, everything in the log.
  • → Intent: purpose, conditions to keep true, limits, budget, when to come back.
  • → Loop: sense → compare → plan → act. Irreversible steps gated, all logged. Back to you only on exceptions.
  • METR study: experienced devs 19% slower with AI tools, believed 20% faster.
  • → “So stop writing better prompts. Write intent an agent can check itself against, and keep the record that lets you check it too.”

Terms

Intent
What to achieve and keep true, within limits, instead of steps and a finish line.

Clear the context. Keep the state.

23:15–24:25 · 5 presses
“Raise your hand if an agent has lost the plan halfway through a long session.”
The context window is working memory. The handoff file is the record.
  • → Hands: an agent lost the plan halfway through?
  • → Hands for each: context rot or context bloat?
  • → Rot: quality drops as the window fills. Bloat: stale output and dead ends fill it. Bloat causes rot.
  • → “What's a handoff file?” Take one answer.
  • → HANDOFF.md: goal · files changed · decisions and why · dead ends · next step · test command + result. Then clear and resume from it.
  • “If you try LEDGER, or break it, I'd love to hear about it. Thank you.”

Terms

Context rot
Answer quality dropping as the context window fills.
Context bloat
The window filling with stale tool output, logs and dead ends.
Handoff file
A short state file written after each task so a fresh session can resume.

Quick Q&A

Isn't this just guardrails?
Guardrails classify text. This checks what actions did, against sensors. Different layer.
Doesn't search blow up?
On raw actions, yes. That's why plan actions are few and coarse.
Prompt injection?
It doesn't stop the text arriving; it stops text causing an unverified action. Malicious intent needs authorization, a separate layer.
Why not just a better model?
Same harness on a local 27B: same guarantees. And stronger models game tests more.
Claude Code, Codex, Antigravity?
They have gates. Antigravity's Artifacts are closest to a record, but the agent writes them and nothing checks them.
Has anyone shipped GATS ideas?
Pieces: Stagehand caches browser actions; MCP tool annotations; Temporal and LangGraph replay. Nobody plans without the model or logs false claims as incidents.
Determinism with a stochastic LLM?
Plans are deterministic; model outputs are journaled as blobs, so replay is bit-exact.
